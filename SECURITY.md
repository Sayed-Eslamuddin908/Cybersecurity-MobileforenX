# Security Policy

## Supported Versions

Security fixes are intended for the latest maintained version of MobileForenX.

| Version | Supported |
| --- | --- |
| Latest release | Yes |
| Older releases | Best effort |
| Unreleased development versions | Best effort |

## Reporting a Vulnerability

Please do not publish sensitive vulnerability details, credentials, private evidence, or exploitable secrets in a public GitHub issue.

When possible, report security issues privately to the project maintainer through the repository's available private reporting mechanism.

Include:

- Affected version or commit.
- A concise description.
- Steps to reproduce in a safe test environment.
- Expected behavior.
- Actual behavior.
- Potential impact.
- Any suggested remediation.

Use synthetic or non-sensitive data when demonstrating an issue.

## Sensitive Data

Never include the following in an issue, pull request, commit, or public repository:

- Real forensic evidence.
- Personally identifiable information.
- Passwords.
- API keys.
- Access tokens.
- Private keys.
- Authentication cookies.
- Confidential case information.

## Evidence Handling

MobileForenX can be used with sensitive forensic material. Users are responsible for following applicable evidence-preservation, privacy, security, and chain-of-custody procedures.

## Scope

This policy covers the MobileForenX source code and project infrastructure maintained in this repository.

Third-party dependencies should be reported according to their respective security policies when the issue is not caused by MobileForenX.
